[id="katello-release-notes"]
= Katello {KatelloVersion} release notes

[id="katello-headline-features"]
== Headline features

Container image push from {SmartProxies}::
+
--
{SmartProxies} can now pull container images from and push them to the container registry on {ProjectServer} by using their SSL client certificate.
Enable this per {SmartProxy} with the *Container Registry Authentication* checkbox or the `container_registry_auth_enabled` API parameter.
A {SmartProxy} can only access container repositories of the organizations it is assigned to.
New repositories created by pushing container images are now stored as regular container repositories in Pulp.
--

Debug certificate algorithm selection::
+
--
The `download_debug_certificate` API endpoint now accepts the optional `key_algorithms` and `signature_algorithms` parameters, which take algorithm OIDs and are passed to Candlepin.
The Edit Organization page has a new drop-down list for the debug certificate algorithm, which offers the key algorithm of the Candlepin CA certificate.
On most deployments, this is RSA only.
This prepares Katello for deployments that use post-quantum cryptography algorithms such as ML-DSA.
If you omit these parameters, the debug certificate is generated as before.
--

Download policy for Python repositories::
+
--
You can now set the download policy of Python repositories to *On Demand* or *Immediate*, as for other repository types.
New Python repositories use the *Default Custom Repository download policy* setting, which defaults to *Immediate*.
--

Files pages migrated to PatternFly 5::
+
--
The Files list and file details pages have been moved to the generic content pages, which use the PatternFly 5 design standard.
The file details page shows the Library repositories and content views that contain the file.
--

New Hammer subscription manifest and repository information::
+
--
The new `hammer subscription manifest-info` command shows the subscription manifest details of an organization.
The `hammer repository info` command now shows whether a repository is orphaned.
--

Pulp 3.118 required::
+
--
Katello now requires Pulp 3.118.
If you interact directly with Pulp APIs, consult the https://pulpproject.org/pulpcore/changes/[Pulp changelog] for changes since Pulp 3.105.
--

[id="katello-upgrade-warnings"]
== Upgrade warnings

Allow multiple content views setting removed::
+
--
The `allow_multiple_content_views` setting has been removed.
Hosts and activation keys can always have multiple content view environments, which was already the default behavior.
If you set `allow_multiple_content_views` to `false`, hosts that register with multiple activation keys are now assigned the content view environments of all the activation keys, instead of only the last one.
Remove the setting from any scripts or automation.
--

Content view and lifecycle environment host columns removed::
+
--
The separate *Content view* and *Lifecycle environment* columns have been removed from the All Hosts page, the legacy Hosts page, and the host CSV export.
Use the *Content view environments* column instead.
Update any scripts that parse the *Content View* or *Lifecycle Environment* columns of the host CSV export.
--

Subscription allocation permission scoped to organizations::
+
--
The `manage_subscription_allocations` permission is now enforced per organization.
During the upgrade, the resource type of this permission changes from Subscription to Organization.
Users can manage subscription allocations only in organizations that their role covers.
Review custom roles that grant `manage_subscription_allocations`.
--

Download policy of Python repositories::
+
--
Before Katello 5.1, Python repositories always used the *On Demand* download policy.
During the upgrade, existing Python repositories are set to *On Demand*, so their behavior does not change.
Python repositories that you create after the upgrade use the *Default Custom Repository download policy* setting, which defaults to *Immediate*.
To download Python content only when it is requested, set the download policy of new Python repositories to *On Demand*.
--
