[id="foreman-release-notes"]
= Foreman {ProjectVersion} release notes

[id="foreman-headline-features"]
== Headline features

ifndef::satellite,orcharhino[]
Edit host parameters in bulk::
On the All Hosts page, select multiple hosts and choose *Set parameters* to set a host-level override for a global parameter.
Select the parameter and enter a value to apply.
This action requires the `edit_hosts`, `view_params`, and `edit_params` permissions.
Without `create_params`, hosts without an existing override are skipped.

OpenVox provisioning templates::
Provisioning templates can now configure OpenVox 8 or 9 repositories for Kickstart, Preseed, and other workflows.
When Puppet setup is enabled, set the `enable-openvox8-repo` or `enable-openvox9-repo` host parameter to `true` to configure an OpenVox repository.
AutoYaST templates support OpenVox, and FreeBSD provisioning now defaults to OpenVox 8 when agent setup is enabled.

HTTP proxy for Ubuntu autoinstall::
Ubuntu autoinstall provisioning can now use an HTTP proxy.
Set the `http-proxy` host parameter to the proxy hostname.
If needed, set `http-proxy-port` to the port.

VM-specific SSH provisioning usernames::
For image-based SSH provisioning, {Project} uses the username exposed by the compute provider's virtual machine object, if available.
Otherwise, {Project} uses the image username.

Keep existing network connections during Kickstart provisioning::
Set the `network-no-activate` host parameter to `true` to add `--no-activate` to Kickstart network directives for managed interfaces.
This can help avoid disrupting an existing bonded connection during provisioning.

Parse URLs in templates::
The `parse_url` template helper lets you extract components from a URL.
For example, use it to obtain the hostname or fragment in a provisioning template.
endif::[]

[id="foreman-upgrade-warnings"]
== Upgrade warnings

ifndef::satellite,orcharhino[]
Authorization changes for host templates and user settings::
Accessing host templates through the API now requires `view_provisioning_templates` as well as access to the host.
Rendered templates can contain sensitive host data, so review host access before granting this permission.
Creating personal access tokens or SSH keys for another user, or viewing or changing another user's email notifications, now requires `edit_users` permission for that user as well as the existing action-specific permission.
Ensure any `edit_users` filter includes the target user, and review custom roles and API clients before upgrading.

Local PostgreSQL upgrades on Enterprise Linux 9::
On Enterprise Linux 9, the installer upgrades eligible local PostgreSQL clusters to version 16.
PostgreSQL 13 upgrades through version 15; PostgreSQL 15 upgrades directly to version 16.
Plan downtime and verify your backup before upgrading.
+
The installer checks that `/var/lib/pgsql` has free space equal to at least twice the apparent size of `/var/lib/pgsql/data` for PostgreSQL 13, or once its size for PostgreSQL 15.
This is a minimum check, not a guarantee of sufficient space: allow extra headroom and check any separate filesystems used by the cluster.
The installer does not upgrade remote databases.

Duplicate organizations, locations, and host groups::
During the upgrade, database migrations rename existing duplicate organizations, locations, and host groups with the same parent.
The record with the lowest ID keeps its name; the others usually have their ID appended.
Names are compared without regard to case.
Check automation that refers to these names or their paths after the upgrade.

Legacy Hammer SSH plugin::
The installer no longer manages the legacy `hammer-cli-foreman-ssh` plugin through its former option.
Applying the legacy `foreman::cli::ssh` Puppet class now removes the plugin package.
RPM upgrades can also remove older versions of the plugin through `foreman-obsolete-packages`.
Review automation that uses `hammer host ssh` before upgrading.
This change does not remove SSH or remote execution generally.

Hammer parameter output::
In `hammer-cli-foreman` 5.1.0, the parameter output change also affects human-readable, JSON, and YAML output and can omit fields such as `is_property`.
Review scripts that consume this output before upgrading.

Smart Proxy TLS cipher restrictions::
Custom Smart Proxy cipher restrictions might not apply to every enabled TLS version.
On Ruby/OpenSSL builds without `SSLContext#ciphersuites=`, `tls_ciphers` does not restrict TLS 1.3 ciphers.
A cipher string valid for only one TLS version can also leave another enabled version unrestricted by that string.
Test the effective cipher configuration for each enabled TLS version.
endif::[]

[id="foreman-deprecations"]
== Deprecations

Foreman server on Debian 12 and Ubuntu 22.04::
Running the Foreman server on Debian 12 (Bookworm) and Ubuntu 22.04 (Jammy) was deprecated in Foreman 5.0.
Both remain supported in Foreman 5.1, but you should plan to move to a newer supported platform.
This deprecation concerns the Foreman server, not clients.
