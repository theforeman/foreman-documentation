= Configuring log retention and disk space limits

[role="_abstract"]
You can configure `journald` retention settings to control how much disk space logs consume on the `/var` partition.
Without retention limits, logs can fill the disk on busy {ProjectServer} hosts.

.Prerequisites
* You have root access to the {ProjectServer} host.

.Procedure
. Create a drop-in configuration file with retention settings recommended for {Project}:
+
[options="nowrap", subs="+quotes,verbatim,attributes"]
----
# mkdir -p /etc/systemd/journald.conf.d
# cat > /etc/systemd/journald.conf.d/10-{project-context}-retention.conf << EOF
[Journal]
Storage=persistent
SystemMaxUse=10G
SystemKeepFree=5G
MaxRetentionSec=4week
MaxFileSec=1week
Compress=yes
EOF
----
+
Adjust the values to match your environment.
For the full list of `journald` parameters, see the RHEL documentation linked below.
. Restart the `systemd-journald` service to apply the new settings:
+
[options="nowrap", subs="+quotes,verbatim,attributes"]
----
# systemctl restart systemd-journald
----

.Verification
* Verify that the reported disk usage does not exceed the `SystemMaxUse` value after `journald` completes its next rotation cycle:
+
[options="nowrap", subs="+quotes,verbatim,attributes"]
----
# journalctl --disk-usage
----

.Troubleshooting
* If `SystemMaxUse` does not appear to take effect,
ifdef::satellite[]
see https://access.redhat.com/solutions/7026910[Known issue with SystemMaxUse] in the _{Team} Knowledgebase_.
endif::[]
ifndef::satellite[]
check that the `Storage=persistent` setting is enabled and that the `/var/log/journal/` directory exists.
endif::[]
Ensure that the drop-in file name begins with a number so that it is loaded in the correct order.
