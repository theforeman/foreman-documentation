= {Project} search query reference

[role="_abstract"]
Use search query syntax and operators in {Project} to filter resources in the {ProjectWebUI}, Hammer CLI, and API.
Parameter-based queries find resources faster and more precisely than free-text search in large inventories.

Search queries follow the pattern:

[options="nowrap", subs="+quotes,attributes"]
----
parameter operator value
----

To search text with whitespaces, enclose it in quotes:

[options="nowrap", subs="+quotes,attributes"]
----
hostgroup = "Web Servers"
----

Typing without specifying a parameter searches across multiple fields simultaneously, also known as free-text search.
For example, typing `64` in the search bar on the hosts page displays all hosts that have `64` in their name, IP address, MAC address, and architecture.

[NOTE]
====
Free-text search is slower and less accurate than parameter-based queries.
Use specific parameters whenever possible for better performance and precision.
====

The search bar supports multiple date and time formats, including the following:

* "10 January 2017"
* "10 Jan 2017"
* 10-January-2017
* 10/January/2017
* "January 10, 2017"
* Today, yesterday, and similar keywords

.Comparison operators accepted by search
[cols="2,2,8",options="header"]
|====
|Operator |Short Name |Description
| = | EQUALS .2+| Accepts numerical, temporal, or text values.
For text, exact case-sensitive matches are returned.
| != | NOT EQUALS
| ~ | LIKE .2+| Accepts text or temporal values.
The search is not case-sensitive.
Accepts the following wildcards: _ for a single character, % or * for any number of characters including zero.
If no wildcard is specified, the string is treated as if surrounded by wildcards: %rhel7%
| !~ | NOT LIKE
| &gt; | GREATER THAN .2+| Accepts numerical or temporal values.
For temporal values, the operator &gt; is interpreted as "later than", and &lt; as "earlier than".
Both operators can be combined with EQUALS: &gt;= &lt;=
| &lt; | LESS THAN
| ^ | IN .2+| Compares an expression against a list of values, as in SQL.
Returns matches that contain or not contain the values, respectively.
| !^ | NOT IN
| HAS or set? | {nbsp} .2+| Returns values that are present or not present, respectively.
| NOT HAS or null? | {nbsp}
|====

.Logical operators accepted by search
[cols="2,1,1,1",options="header"]
|====
|Operator 3+| Alternative Notations
| and | &amp; | &amp;&amp; | &lt;whitespace&gt;
| or | \| | \|\| | {nbsp}
| not | – | ! | {nbsp}
|====

.Useful search examples
====
These examples show how to filter hosts by using host attribute search parameters.
You can use them on {ProjectWebUI} pages that list hosts, such as *Hosts* > *All Hosts*.
You can apply the same syntax to filter other resources on other {ProjectWebUI} pages.

Find hosts by host global status and sub-status::
Hosts that have an *OK* global status:
+
[options="nowrap", subs="+quotes"]
----
global_status = ok
----
+
Hosts that have an *Error* or *Warning* global status:
+
[options="nowrap", subs="+quotes"]
----
global_status = error or global_status = warning
----
+
Hosts that have at least one pending resource:
+
[options="nowrap", subs="+quotes"]
----
status.pending > 0
----
+
Hosts that restarted some service during the last run:
+
[options="nowrap", subs="+quotes"]
----
status.restarted > 0
----
+
Hosts that have an interesting last run that might indicate something has happened:
+
[options="nowrap", subs="+quotes"]
----
status.interesting = true
----

Find hosts that need attention::
Hosts with security updates available:
+
[options="nowrap", subs="+quotes,attributes"]
----
errata_status = security_needed
----
+
Hosts that have email notifications for configuration errors enabled and are in a failed state:
+
[options="nowrap", subs="+quotes,attributes"]
----
status.enabled = true AND status.failed = true
----
+
Hosts that have not generated a report recently:
+
[options="nowrap", subs="+quotes,attributes"]
----
last_report < "7 days ago"
----

Find hosts by configuration, environment, or registration date::
Hosts in production that belong to a host group whose name includes a variation of the word "webservers":
+
[options="nowrap", subs="+quotes,attributes"]
----
environment = production AND hostgroup ~ webservers
----
+
Hosts registered in the last month:
+
[options="nowrap", subs="+quotes,attributes"]
----
registered_at > "30 days ago"
----
+
Hosts registered between specific dates:
+
[options="nowrap", subs="+quotes,attributes"]
----
registered_at > 1-January-2026 AND registered_at < 31-January-2026
----

Exclude specific results::
All hosts except hosts in a host group named "exceptions":
+
[options="nowrap", subs="+quotes,attributes"]
----
NOT hostgroup = exceptions
----
+
Hosts that are not compliant with policies:
+
[options="nowrap", subs="+quotes,attributes"]
----
compliance_status != compliant
----
ifndef::satellite[]
+
This search query requires the OpenSCAP plugin.
endif::[]

Use wildcards for flexible matching::
Hosts with names that include the strings "web" and "prod":
+
[options="nowrap", subs="+quotes,attributes"]
----
name ~ web*prod*
----
+
Host groups starting with a specific prefix:
+
[options="nowrap", subs="+quotes,attributes"]
----
hostgroup ~ rhel%
----
====
