= Host distribution and remote execution with load balancing

[role="_abstract"]
The host counts that {Project} displays for individual {SmartProxies} do not represent how the load balancer distributes requests.
Remote execution also uses a separate load-balancing mechanism.

When a host registers through the load balancer, {Project} must assign an individual {SmartProxy} as the content source for the host.
Because {Project} does not know which {SmartProxy} behind the load balancer handles each request, it selects the first {SmartProxy} that has a matching registration URL.
As a result, on the *Infrastructure* > *Smart Proxies* page, one {SmartProxy} can appear to manage most or all hosts while the other {SmartProxies} appear to manage few hosts.
This uneven distribution is expected and does not indicate that the load balancer has stopped distributing content requests.
Do not use these host counts to monitor load-balancer traffic or health.

Remote execution does not send jobs through the external load balancer.
{Project} considers each remote execution {SmartProxy} individually, selects the eligible {SmartProxy} with the fewest running jobs, and connects directly to that {SmartProxy}.

In a load-balanced setup, the *Prefer registered through {SmartProxy} for remote execution* setting does not determine the {SmartProxy} that runs a remote job.
{Project} selects the least-loaded eligible remote execution {SmartProxy} instead.
