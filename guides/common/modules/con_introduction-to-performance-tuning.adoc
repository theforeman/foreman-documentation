= Introduction to performance tuning

[role="_abstract"]
Tune {Project} to improve system response times and handle larger numbers of managed hosts.
Performance tuning helps optimize resource usage and ensures smooth operations as your infrastructure scales.

You can tune {Project} in three primary scenarios:

* Selecting the appropriate deployment size during initial installation
* Optimizing an existing deployment to handle increased load
* Troubleshooting performance degradation

{Project} includes several components that you can tune independently to achieve optimal performance for your environment.
You can tune at the operating system level (tuned profiles, transparent hugepage settings), application level (Puma workers and threads, Apache httpd processes, Dynflow orchestrator, remote execution transport), database level (PostgreSQL configuration), and caching level (Redis configuration).

ifdef::katello,orcharhino,satellite[]
For Smart Proxy Server deployments, you can also tune Smart Proxy configuration and run performance tests.
endif::[]

Before tuning your deployment, review the hardware and software requirements in {InstallingServerDocURL}preparing-your-environment-for-{project-context}-server-installation[Preparing your environment for {ProjectServer} installation] in _{InstallingServerDocTitle}_.
Most configuration changes require a {Project} restart, so test all tuning changes in a non-production environment with valid backups and set up monitoring to evaluate the effectiveness of changes in your specific environment.

Your environment may differ from the testing environment used to develop these recommendations, so results may vary.

Optional: After any change, run this {Project} health check:

ifdef::containerized[]
[options="nowrap" subs="attributes"]
----
$ {foremanctl} health
----
endif::[]
ifndef::containerized[]
[options="nowrap" subs="attributes"]
----
$ {foreman-maintain} health check
----
endif::[]
