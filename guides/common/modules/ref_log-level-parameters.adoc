= Log level parameters

[role="_abstract"]
You can control the log detail level of containerized {Project} services with the `{foremanctl} deploy` log level parameters.

The `--log-level` parameter sets the global baseline for all services.
The valid values are: `debug`, `info`, `warn`, `error`, `fatal` out of which `info` is the default.

Per-service parameters override this value and translate it to the native vocabulary of each service:

`--foreman-log-level`::
Foreman service.
Values: `debug`, `info`, `warn`, `error`, `fatal`.

`--foreman-proxy-log-level`::
{SmartProxyServer}.
Values: `debug`, `info`, `warn`, `error`, `fatal`.

`--pulp-log-level`::
Pulp services (`pulpcore-api`, `pulpcore-content`, `pulpcore-worker`).
Values: `debug`, `info`, `warning`, `error`, `critical`.

`--valkey-log-level`::
Valkey.
Independent of `--log-level`.
Values: `debug`, `verbose`, `notice`, `warning`, `nothing`.
Default: `notice`.

ifdef::satellite,katello,orcharhino[]
These services do not have dedicated `{foremanctl} deploy` log level parameters and are not affected by the global `--log-level` parameter.

* Candlepin
* PostgreSQL
* httpd
endif::[]
