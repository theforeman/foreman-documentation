= {Project} deployment components

[role="_abstract"]
A typical {Project} deployment consists of the following components: a {ProjectServer}, {SmartProxyServers}, and hosts that receive
ifdef::katello,orcharhino,satellite[]
content and
endif::[]
configuration from {ProjectServer} and {SmartProxyServers}.

ifdef::containerized[]
{Project} uses Podman, a container engine, to run {Project} application services in containers.
`systemd` generates service units from declarative Podman configuration files, integrating container lifecycle management with `systemd` service control.

You do not need container expertise to install and operate {Project}.
Podman is a standard component of {EL}.
To install, configure, and maintain {Project}, you use the `{foremanctl}` utility which deploys the Podman containers.
endif::[]

{ProjectServer}::
{ProjectServer} is the central component of your {Project} deployment.
A typical {Project} deployment includes one {ProjectServer}.
{ProjectServer} can include a built-in {SmartProxy}
ifdef::foreman-deb,foreman-el[]
and delegates host provisioning and communication to {SmartProxyServers}.
endif::[]
ifdef::katello,orcharhino,satellite[]
and can delegate content distribution, host provisioning, and communication to {SmartProxyServers}.
endif::[]

{SmartProxyServer}::
With {SmartProxyServers}, you can extend the reach and scalability of your {Project} deployment by running localized services closer to your hosts.

Hosts in {Project}::
A host is any Linux client that {ProjectName} manages.
ifndef::satellite[]
{Project} can also manage some non-Linux clients, such as Windows, BSD, and Solaris.
Note that not all {Project} functionality might be available on these hosts.
endif::[]
+
Hosts can be physical or virtual.
You can deploy virtual hosts on any platform supported by {ProjectName}.
