= Provision virtual machines on {KubeVirt}

[role="_abstract"]
You can create a compute resource for {KubeVirt} to provision and manage virtual machines in {Kubernetes} by using {Project}.
{KubeVirt} enables development teams to run existing virtual machine workloads alongside containerized applications in {Kubernetesfirst}.

ifdef::satellite[]
Note that template provisioning is not supported for this release.

:FeatureName: The {KubeVirt} compute resource
include::snip_technology-preview.adoc[]
endif::[]

Before you start provisioning virtual machines on {KubeVirt}, ensure that your environment meets the following requirements:

* You must have the `get`, `delete`, `create`, `update`, `patch`, `list`, and `watch` permissions for VMs and other {KubeVirt} resources for the {Kubernetes} cluster in the specified namespace.
You can get these permissions with the `kubevirt.io:edit` cluster role.
* To use auto-completion for network selection, you must have the `get` and `list` permissions for the `network-attachment-definitions.k8s.cni.cncf.io` resource.
{Project} lists network attachment definitions in all namespaces, so these permissions must be granted cluster-wide.
* In the specified namespace, you must also have the permissions to create, get, update, patch, and delete secrets, to create, get, list, and delete persistent volume claims, to create, get, list, and delete `datavolumes` and `datasources` of the `cdi.kubevirt.io` API group, and to create the `datavolumes/source` subresource.
{Project} stores user data in a secret, creates persistent volume claims for network-based hosts, and clones a data source for image-based hosts.
* You must have the `get` and `list` permissions for the `storageclasses.storage.k8s.io` resource, granted cluster-wide.
Without them, the storage class list in the virtual machine form is empty.
* Virtual machines must receive MAC addresses when they are created, for example from KubeMacPool.
{KubeVirt} assigns MAC addresses only when a virtual machine starts, and {Project} cannot match the host's network interface without one.
* For image-based provisioning, the Containerized Data Importer (CDI) must know the access modes of your storage class.
If the storage profile of the storage class has no access modes, which is the case for storage provisioners that CDI does not recognize, add them to the `claimPropertySets` of the storage profile.

include::snip_prerequisites-common-compute-resource.adoc[]

* A {SmartProxyServer} managing a network on the {Kubernetes} cluster.
Ensure that no other DHCP services run on this network to avoid conflicts with {SmartProxyServer}.
* Ensure the provisioning user has the required permissions to provision hosts.
