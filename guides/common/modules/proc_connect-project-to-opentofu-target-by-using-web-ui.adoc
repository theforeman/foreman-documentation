= Connect {Project} to {opentofu-target} by using {ProjectWebUI}

[role="_abstract"]
You can use {Project} with the OpenTofu plugin to provision, manage, and decommission hosts on {opentofu-target}.

ifdef::hetzner-cloud,stackit-cloud[]
.Prerequisites
ifdef::hetzner-cloud[]
* You have an API token for your {opentofu-target} account.
You can create the token on the Hetzner Console web interface.
endif::[]
ifdef::stackit-cloud[]
* You have the project ID and service account key for your {opentofu-target} account.
You can find both on the STACKIT web interface.
endif::[]
endif::[]

.Procedure
. In the {ProjectWebUI}, navigate to *Infrastructure* > *Compute Resources*.
. Click *Create Compute Resource*.
. In the *Name* field, enter a name for the compute resource, for example, `{opentofu-target}`.
+
Append the name of your {opentofu-target} account if you plan to use multiple accounts simultaneously.
. From the *Provider* list, select *OpenTofu*.
. Optional: In the *Description* field, enter a description for your compute resource.
. From the *OpenTofu Provider* menu, select `{opentofu-target}`.
. From the *OpenTofu Template* menu, select `{opentofu-target} provision default`.
ifdef::hetzner-cloud[]
. In the *Token* field, enter your {opentofu-target} token.
endif::[]
ifdef::stackit-cloud[]
. In the *Project ID* field, enter the ID of your {opentofu-target} project.
. In the *Service account key* field, enter the key of your {opentofu-target} service account.
You must paste the whole JSON file provided by {opentofu-target}.
endif::[]
. Check *Enable caching* to cache API calls to {opentofu-target} about clusters, network, or storage lists on {Project} for 60 minutes.
+
{Team} recommends to enable caching to improve performance.
. Click *Submit*.

.Next steps
* Define an image from your compute resource provider in {Project} to perform image-based host provisioning.
For more information, see xref:define-an-image-for-hosts-on-{opentofu-target-id}-by-using-web-ui[].
