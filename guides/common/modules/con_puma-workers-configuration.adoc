= Puma workers configuration

[role="_abstract"]
Worker count determines how many parallel processes handle incoming requests.
The relationship between CPU resources and worker count directly impacts {Project} performance scaling, particularly for concurrent operations like host registrations.

If you have enough CPUs, adding more workers improves performance.
For example, we have compared {Project} setups with 8 and 16 CPUs:

.{foreman-installer} options used to test effect of workers count
[width="100%",cols="50%,50%",options="header",]
|===
|{Project} VM with 8 CPUs, 40 GiB RAM |{Project} VM with 16 CPUs, 40 GiB RAM
|`--foreman-foreman-service-puma-threads-max 16` |`--foreman-foreman-service-puma-threads-max 16`
|`--foreman-foreman-service-puma-workers {2\|4\|8\|16}` |`--foreman-foreman-service-puma-workers {2\|4\|8\|16}`
|===

In an 8 CPU setup, changing workers from 2 to 16 improved concurrent registration time by 36%.
In a 16 CPU setup, the same change improved it by 55%.

More workers also increase total registration concurrency.
In our tests, 2 workers handled up to 480 concurrent registrations.
More workers improved this.
