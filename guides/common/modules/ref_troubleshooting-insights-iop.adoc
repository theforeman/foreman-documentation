= Troubleshooting {insights-iop}

[role="_abstract"]
You can check the logs to troubleshoot issues with {insights-iop}.

ifndef::containerized[]
To troubleshoot hosts monitoring, you can find the logs in the `/var/log/foreman/production.log` file.
endif::[]

ifdef::containerized[]
The names of all {insights-iop} services have the `iop` prefix.
To view the logs for all {insights-iop} services, enter the following command:

[options="nowrap" subs="+quotes,attributes"]
----
# journalctl --unit "iop*"
----

For the full list of commands to view and filter service logs, such as following log output in real time or tracing a request by its correlation ID, see {AdministeringDocURL}viewing-service-logs[Viewing service logs] in _{AdministeringDocTitle}_.

If you expect new CVEs but do not see them on the *Vulnerability* page, consider updating the vulnerability metadata by synchronizing.
You can trigger a scan by synchronizing a repository.
When you update a host, {Project} pulls any missing CVEs during vulnerability evaluation.
If you need to refresh the metadata manually, you can start the vulnerability metadata download service:

[options="nowrap" subs="+quotes,attributes"]
----
# systemctl start iop-vuln-metadata-download.service
----

[NOTE]
====
The download service relies on a single-threaded scan.
If synchronization is already in progress, the service might fail or time out.
====
endif::[]
