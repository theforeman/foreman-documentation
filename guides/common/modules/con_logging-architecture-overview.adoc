= Logging architecture overview

[role="_abstract"]
{ProjectServer} manages all service logs using a centralized system built on `systemd` and `journald`.
Rather than searching through individual log files across different directories, you can manage all service activity through a single, unified pipeline.

All {Project} services send their log output to `stdout` by default.
The container runtime automatically captures this data stream and passes it to the logging daemon.

Key components of the logging architecture include:

* `journald` serves as the central logging service.
It receives streams from the container runtime, formats the entries, and handles temporary or persistent log storage.
By default, `journald` stores log data in volatile memory, meaning all log history is cleared whenever the system reboots.
To retain log history across system restarts, you must explicitly enable persistent storage in your `journald` configuration.

* `journalctl` is the primary management tool.
Use this command to view, search, and filter logs for any service from a single interface.

* `{foremanctl} deploy` with the appropriate parameters modifies log levels or adjusts logging verbosity.
