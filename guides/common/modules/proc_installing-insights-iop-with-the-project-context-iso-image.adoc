= Installing {insights-iop} with the {Project} ISO image

[role="_abstract"]
You can use the {Project} installation ISO image to access the required container content.

.Prerequisites
* `skopeo` is installed on your {ProjectServer}.
ifdef::satellite[]
For more information, see {RHELDocsBaseURL}9/html/building_running_and_managing_containers/assembly_starting-with-containers_building-running-and-managing-containers#proc_getting-container-tools_assembly_starting-with-containers[Getting container tools] in _{RHEL}{nbsp}9 Building, running, and managing containers_.
endif::[]
ifndef::satellite[]
+
[options="nowrap", subs="+quotes,verbatim,attributes"]
----
# {project-package-install} skopeo
----
endif::[]

.Procedure
. Download and mount the {Project} ISO image:
For more information, see xref:preparing-the-system-for-{Project}-deployment-from-the-offline-repositories[].
. Set up the local repositories and containers for disconnected environments:
+
[options="nowrap", subs="+quotes,verbatim,attributes"]
----
# /media/satellite/prepare_system
----
. Download the required vulnerability metadata files:
+
--
* `cvemap.xml`: The CVE map that {Project} serves locally for VMAAS vulnerability correlation.
* `cpe-dictionary.xml`: Common Platform Enumeration (CPE) data for vulnerability assessment.
* `repository-to-cpe.json`: The mapping of repositories to CPE identifiers.
* `vex-latest.tar.zst`: CSAF VEX (Vulnerability Exploitability eXchange) data.
--
+
[options="nowrap" subs="+quotes,attributes"]
----
$ curl -o cvemap.xml https://security.access.redhat.com/data/meta/v1/cvemap.xml
$ curl -o cpe-dictionary.xml https://security.access.redhat.com/data/meta/v1/cpe-dictionary.xml
$ curl -o repository-to-cpe.json https://security.access.redhat.com/data/metrics/repository-to-cpe.json
----
+
For `vex-latest.tar.zst`:

.. Retrieve the name of the latest archive from `archive_latest.txt`:
+
[options="nowrap" subs="+quotes,attributes"]
----
$ curl https://security.access.redhat.com/data/csaf/v2/vex/archive_latest.txt
----
.. Download the archive and save it as `vex-latest.tar.zst`.
.. Replace _archive_name_ with the file name that `archive_latest.txt` returns:
+
[options="nowrap" subs="+quotes,attributes"]
----
$ curl -o vex-latest.tar.zst https://security.access.redhat.com/data/csaf/v2/vex/_archive_name_
----
. Transfer the `cvemap.xml`, `cpe-dictionary.xml`, `repository-to-cpe.json`, and `vex-latest.tar.zst` files to your disconnected {ProjectServer}.
. Copy the files to `/var/lib/foreman/`:
+
[options="nowrap" subs="+quotes"]
----
# cp cvemap.xml cpe-dictionary.xml repository-to-cpe.json vex-latest.tar.zst /var/lib/foreman/
----
+
The target directory defaults to `/var/lib/foreman/` and is configurable: the `cvemap.xml`, `cpe-dictionary.xml`, and `repository-to-cpe.json` files use the `iop_vuln_metadata_downloader_manual_dir` setting, and the `vex-latest.tar.zst` file uses the `iop_vex_downloader_manual_dir` setting.
{Project} watches this directory and, after the plugin is enabled, automatically publishes the files under `/var/www/html/pub/iop/data/`: `cvemap.xml` and `cpe-dictionary.xml` to `meta/v1/`, `repository-to-cpe.json` to `metrics/`, and `vex-latest.tar.zst` to `csaf/v2/vex/`.
While these files are present, the vulnerability metadata downloader remains in offline mode and does not attempt to download them over the network.
. Enable the {insights-iop} plugin:
+
[options="nowrap", subs="+quotes,verbatim,attributes"]
----
# {foremanctl} deploy --add-feature iop
----
