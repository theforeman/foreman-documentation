= Build a custom Discovery image

[role="_abstract"]
You can build a custom Discovery ISO or rebuild an ISO if you change configuration files.

The Discovery image uses a minimal operating system that is booted on hosts to acquire initial hardware information and check in with {Project}.
Discovered hosts keep running the Discovery operating system until they start an operating system installer, either by rebooting or by using kexec, which then initiates the provisioning process.

[IMPORTANT]
====
Do not use your production {ProjectServer} nor {SmartProxyServer} to perform this procedure.
Use either a dedicated environment or copy the repositories and Kickstart file to a separate system.
====

The following procedure demonstrates the building process on CentOS Stream 9.

.Prerequisites
* A dedicated CentOS Stream 9 system, for example a virtual machine.
* Hardware virtualization is available on your system, unless you build in the `novirt` mode.
* The following packages are installed:
** `anaconda`
** `git-core`
** `lorax`
** `pykickstart`
** `qemu-kvm`
** `wget`
* The `foreman-discovery-image` repository is cloned:
+
[options="nowrap" subs="+quotes"]
----
$ git clone https://github.com/theforeman/foreman-discovery-image.git
$ cd foreman-discovery-image
----

.Procedure
. Prepare the Kickstart file with the repositories of {Project} {ProjectVersion}:
+
[options="nowrap" subs="+quotes,attributes"]
----
$ ./build-kickstart fdi-stream9.ks {ProjectVersion}
----
+
The second argument replaces `nightly` in the URLs of the {Project} repositories.
. Build the ISO image:
+
[options="nowrap" subs="+quotes"]
----
$ sudo ./build-livecd-root _custom_ ./result "nomodeset nokaslr"
----
+
`nomodeset` disables mode setting.
`nokaslr` disables address space layout randomization.
+
By default, the build runs the installer in a virtual machine.
To build on the dedicated system itself, for example in a virtual machine without nested virtualization, add `novirt` as the fourth argument.
+
For example, you can build a fully automated Discovery image with a static network configuration:
+
[options="nowrap", subs="+quotes,verbatim,attributes"]
----
$ sudo ./build-livecd-root _custom_ ./result \
"nomodeset nokaslr \
fdi.pxip=192.168.140.20/24 fdi.pxgw=192.168.140.1 \
fdi.pxdns=192.168.140.2 proxy.url=https://{foreman-example-com}:8443 \
proxy.type=foreman fdi.pxmac=52:54:00:be:8e:8c fdi.pxauto=1"
----
+
For more information about configuration options, see xref:kernel-parameters-for-discovery-customization[].
. Verify that your `./result/fdi-custom-XXXXXXX.iso` file is created:
+
[options="nowrap" subs="+quotes"]
----
$ ls -h ./result/*.iso
----
. Convert the `.iso` file to an `.iso` hybrid file for local booting:
+
[options="nowrap" subs="+quotes"]
----
# isohybrid --partok fdi.iso
----
+
If you have `grub2` packages installed, you can also use the following command to install a `grub2` boot loader:
+
[options="nowrap" subs="+quotes"]
----
# isohybrid --partok --uefi fdi.iso
----
. Add `md5` checksum to the `.iso` file so that it can pass installation media validation tests in {Project}:
+
[options="nowrap" subs="+quotes"]
----
# implantisomd5 --force fdi.iso
----
+
The build already embeds a checksum, and `isohybrid` changes the file.
Without `--force`, `implantisomd5` does not replace the checksum and the default boot entry of the ISO fails its media check.
