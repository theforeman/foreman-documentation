= Defining lifecycle environments

[role="_abstract"]
Lifecycle environments represent stages in your content promotion pipeline.
By adding lifecycle environments, you define the stages through which you will be promoting your content as you test it.

Every {Project} deployment starts with an initial *Library* lifecycle environment that holds all synchronized content.
From there, you create a lifecycle environment path that matches the stages your content passes through before reaching your hosts.

For example, consider a team managing web servers.
They want to test package updates in a development environment first, then validate them further in a testing environment, and only then promote the packages to production.
The resulting lifecycle environment path looks like this: *Library* > *Development* > *Testing* > *Production*.

In this example, you create that path.

.Procedure
. In the {ProjectWebUI}, navigate to *Content* > *Lifecycle* > *Lifecycle Environments*.
. Add an environment path:
.. Click *Create Environment Path* to start a new lifecycle environment path.
.. In the *Name* field, enter `Development`.
.. Click *Save*.
. Extend the environment path with a testing stage:
.. Click *Add New Environment* next to the *Development* environment.
.. In the *Name* field, enter `Testing`.
.. Ensure that the *Prior Environment* dropdown list value is set to *Development*.
.. Click *Save*.
. Extend the environment path with a production stage:
.. Click *Add New Environment* next to the *Testing* environment.
.. In the *Name* field, enter `Production`.
.. Ensure that the *Prior Environment* dropdown list value is set to *Testing*.
.. Click *Save*.

.Verification
* In the {ProjectWebUI}, navigate to *Content* > *Lifecycle* > *Lifecycle Environments*.
Review your new lifecycle environment path.
