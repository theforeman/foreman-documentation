= Setting service log levels

[role="_abstract"]
At the initial deployment, when the containers are first created, you can set the log level for {Project} services by using `{foremanctl} deploy` parameters.

Persistent log levels are part of the server configuration and survive restarts.

You can:

* set a global baseline log level for all services that support per-service log level configuration,
* override the global level for individual services by using service-specific parameters.

.Procedure
* To set the global log level for all supported services, run:
+
[options="nowrap", subs="+quotes,verbatim,attributes"]
----
# {foremanctl} deploy --log-level _<option>_
----
+
For example, to set the global log level to `debug`, run:
+
[options="nowrap", subs="+quotes,verbatim,attributes"]
----
# {foremanctl} deploy --log-level debug
----
+
Valid values are `debug`, `info`, `warn`, `error`, and `fatal`.
The default value is `info`.

* To override the log level for a specific service, use a service-specific parameter, such as `--foreman-log-level` and `--foreman-proxy-log-level`.
+
For example, to set only Foreman to `error` while keeping other services at the global level, run:
+
[options="nowrap", subs="+quotes,verbatim,attributes"]
----
# {foremanctl} deploy --foreman-log-level error
----
+
After you complete debugging, reset the log level to the default:
+
[options="nowrap", subs="+quotes,verbatim,attributes"]
----
# {foremanctl} deploy --foreman-log-level info
----
+
[NOTE]
====
Each service inherits the default value from the `log-level` parameter, unless you set the value for the service using the `<service>-log-level` parameter.
Running `foremanctl deploy —log-level <new-value>` or `foremanctl deploy —reset-log-level` will not affect the `—<service>-log-level` parameters.
====
