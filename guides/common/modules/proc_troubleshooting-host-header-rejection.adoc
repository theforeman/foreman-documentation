= Troubleshooting host header rejection

[role="_abstract"]
{Project} rejects HTTP requests whose `Host` header does not match the server FQDN or a declared `--server-alias` with a `403 Forbidden` error.
To allow access from an alternate hostname, declare it as a server alias.

.Procedure
. Confirm that requests with the FQDN succeed:
+
[options="nowrap", subs="+quotes,verbatim,attributes"]
----
# curl -s https://_server.example.com_/api/v2/ping | python3 -m json.tool
----
+
A successful response returns JSON with service status information, for example:
+
[source, none, options="nowrap"]
----
{
    "results": {
        "foreman": {
            "database": {"active": true, "duration_ms": "1"},
            "cache": {"servers": [{"status": "ok", "duration_ms": "0"}]}
        }
    }
}
----
. Confirm that the alternate hostname is rejected:
+
[options="nowrap", subs="+quotes,verbatim,attributes"]
----
# curl -Ik https://_alternate.example.com_/api/v2/ping
----
+
Over HTTPS, you might see the following client-side TLS rejection:
+
[source, none, options="nowrap"]
----
SSL: no alternative certificate subject name matches target hostname 'alternate.example.com'
----
+
If you bypass certificate verification with the `--insecure` option, or connect over HTTP, {Project} returns:
+
[source, none, options="nowrap"]
----
HTTP/1.1 403 Forbidden
----
. If the hostname is legitimate, declare it as a server alias.
For more information, see xref:configuring-an-alternate-cname_{context}[].

.Verification
* Repeat the request for the alternate hostname without the `--insecure` option:
+
[options="nowrap", subs="+quotes,verbatim,attributes"]
----
$ curl -s https://_alternate.example.com_/api/v2/ping | python3 -m json.tool
----
+
The request returns JSON with service status information.
