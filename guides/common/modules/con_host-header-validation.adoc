= Host header validation

[role="_abstract"]
On containerized deployments, {Project} and {SmartProxies} answer only to the hostnames that you declare for them.
A request that uses an undeclared hostname is rejected with a `403 Forbidden` error.
Declare every hostname that clients, load balancers, monitoring systems, and automation use.

{Project} and each {SmartProxy} validate the HTTP `Host` and `X-Forwarded-Host` headers of every incoming request against a list of permitted hostnames.
When a request passes through a reverse proxy or a load balancer, the forwarded hostname must also be permitted.

`{foremanctl}` generates a separate list of permitted hostnames for {Project} and for each {SmartProxy}, from the FQDN and the server aliases for that server.

`{foremanctl}` regenerates the list on every deployment, so edits that you make directly to a settings file do not persist.
To declare an additional hostname, add it as a server alias and run the deployment command for that server again.

Host header validation fails open.
When a list of permitted hostnames is empty, {Project} or the {SmartProxy} that uses that list accepts any hostname.
