= {Project} security capabilities

[role="_abstract"]
{Project} supports multiple security mechanisms for additional layers of protection.
Understanding these capabilities helps you evaluate how {Project} can support the security requirements of your organization.

You can use the following security capabilities in {Project} to enhance the security of your deployment:

Federal Information Processing Standards (FIPS) Mode::
{ProjectServer} and {SmartProxyServers} can run on FIPS-enabled {RHEL} hosts.
Note that {Project} itself is not FIPS-certified.
+
FIPS mode enforces the use of validated cryptographic algorithms and modules.
Enabling FIPS mode ensures that all cryptographic operations within the system adhere to strict security standards.
ifndef::foreman-deb[]
+
[NOTE]
====
{Project} supports DEFAULT and FIPS crypto-policies.
The FUTURE crypto-policy is not supported for {ProjectServer} and {SmartProxyServer} installations.
====
endif::[]
+
If you want to run {ProjectServer} or {SmartProxyServer} on a FIPS-enabled host, FIPS must be enabled on the host before installing.
You cannot enable FIPS mode on {ProjectServer} or {SmartProxyServer} after installation.

File Access Policy Daemon (`fapolicyd`)::
{ProjectServer} and {SmartProxyServers} can run on hosts that have the `fapolicyd` service enabled.
+
The `fapolicyd` daemon helps prevent unauthorized code execution and enhances system integrity by enforcing file access policies.
+
You can enable or disable `fapolicyd` on your {ProjectServer} and {SmartProxyServers} at any time.

Post-Quantum Cryptography (PQC)::
{Project} can synchronize and distribute {RHEL} 10 content signed with the Module-Lattice-Based Digital Signature Standard (ML-DSA).
ML-DSA is a quantum-resistant cryptographic signature algorithm designed to protect content integrity against potential attacks from quantum computers.
+
{Team} does not currently support full PQC compatibility for {Project}.

Security-Enhanced Linux (SELinux)::
{ProjectServer} and {SmartProxyServers} must be run on hosts with SELinux enabled.
+
The SELinux collection of security modules enforces policies that define which processes can access specific system resources, providing protection against unauthorized access and exploitation.
+
To maintain a high-security environment, {Team} recommends running {Project} with SELinux in enforcing mode.
This ensures that access control policies are strictly enforced and minimizes the risk of privilege escalation or unauthorized actions.

In addition to these security capabilities, regularly updating security policies and configurations, as well as monitoring system logs, can help detect and respond to potential threats effectively on both {ProjectServer} and {SmartProxyServer}.

ifdef::satellite[]
For certain use cases, {ProjectServer} must meet security compliance requirements.
You can use Security Content Automation Protocol (SCAP) to scan your system for security policy compliance.
endif::[]
