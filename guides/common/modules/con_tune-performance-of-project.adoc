= Tune performance of {Project}

[role="_abstract"]
Tune {Project} to improve system response times and handle larger numbers of managed hosts.
Performance tuning helps optimize resource usage and ensures smooth operations as your infrastructure scales.

You can tune {Project} in three primary scenarios:

* Selecting the appropriate deployment size during initial installation
* Optimizing an existing deployment to handle increased load
* Troubleshooting performance degradation

{Project} includes several components that you can tune independently to achieve optimal performance for your environment.
ifndef::containerized[]
You can tune at the operating system level (tuned profiles, transparent hugepage settings), application level (Puma workers and threads, Apache httpd processes, Dynflow orchestrator, remote execution transport), database level (PostgreSQL configuration), and caching level ({cache-store} configuration).
endif::[]
ifdef::containerized[]
You can tune the operating system by using tuned profiles and transparent hugepage settings.
To configure your {ProjectServer} to use the optimal amount of CPU cores and memory for the number of hosts that you manage, apply a predefined tuning profile when you deploy your {ProjectServer}.
For more information, see {InstallingServerDocURL}tuning-{project-context}-server-performance-with-predefined-profiles[Tuning {ProjectServer} performance with predefined profiles{InInstallingServerDoc}].
endif::[]

Before tuning your deployment, review the hardware and software requirements in {InstallingServerDocURL}environment-preparation-for-{project-context}-server-installation[Environment preparation for {ProjectServer} installation]{InInstallingServerDoc}.
Most configuration changes require a {Project} restart, so test all tuning changes in a staging environment and set up monitoring to evaluate the effectiveness of changes in your specific environment.

Your environment may differ from the testing environment used to develop these recommendations, so results may vary.
Monitor your deployment health after configuration changes.
{Project} provides a health check command to verify system status.

ifdef::satellite[]
While these guidelines cover many situations, contact Red Hat support if you have a specific use case that is not included.
endif::[]
