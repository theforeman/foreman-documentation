1. Foreman 5.1 release notes

1.1. Headline features

Edit host parameters in bulk

On the All Hosts page, select multiple hosts and choose Set parameters to set a host-level override for a global parameter. Select the parameter and enter a value to apply. This action requires the edit_hosts, view_params, and edit_params permissions. Without create_params, hosts without an existing override are skipped.

OpenVox provisioning templates

Provisioning templates can now configure OpenVox 8 or 9 repositories for Kickstart, Preseed, and other workflows. When Puppet setup is enabled, set the enable-openvox8-repo or enable-openvox9-repo host parameter to true to configure an OpenVox repository. AutoYaST templates support OpenVox, and FreeBSD provisioning now defaults to OpenVox 8 when agent setup is enabled.

HTTP proxy for Ubuntu autoinstall

Ubuntu autoinstall provisioning can now use an HTTP proxy. Set the http-proxy host parameter to the proxy hostname. If needed, set http-proxy-port to the port.

VM-specific SSH provisioning usernames

For image-based SSH provisioning, Foreman uses the username exposed by the compute provider’s virtual machine object, if available. Otherwise, Foreman uses the image username.

Keep existing network connections during Kickstart provisioning

Set the network-no-activate host parameter to true to add --no-activate to Kickstart network directives for managed interfaces. This can help avoid disrupting an existing bonded connection during provisioning.

Parse URLs in templates

The parse_url template helper lets you extract components from a URL. For example, use it to obtain the hostname or fragment in a provisioning template.

1.2. Upgrade warnings

Local PostgreSQL upgrades on Enterprise Linux 9

On Enterprise Linux 9, the installer upgrades eligible local PostgreSQL clusters to version 16. PostgreSQL 13 upgrades through version 15; PostgreSQL 15 upgrades directly to version 16. Plan downtime and verify your backup before upgrading.

The installer checks that /var/lib/pgsql has free space equal to at least twice the apparent size of /var/lib/pgsql/data for PostgreSQL 13, or once its size for PostgreSQL 15. This is a minimum check, not a guarantee of sufficient space: allow extra headroom and check any separate filesystems used by the cluster. The installer does not upgrade remote databases.

Duplicate organizations, locations, and host groups

During the upgrade, database migrations rename existing duplicate organizations, locations, and host groups with the same parent. The record with the lowest ID keeps its name; the others usually have their ID appended. Names are compared without regard to case. Check automation that refers to these names or their paths after the upgrade.

Legacy Hammer SSH plugin

The installer no longer manages the legacy hammer-cli-foreman-ssh plugin through its former option. Applying the legacy foreman::cli::ssh Puppet class now removes the plugin package. RPM upgrades can also remove older versions of the plugin through foreman-obsolete-packages. Review automation that uses hammer host ssh before upgrading. This change does not remove SSH or remote execution generally.

Hammer parameter output

In hammer-cli-foreman 5.1.0, the parameter output change also affects human-readable, JSON, and YAML output and can omit fields such as is_property. Review scripts that consume this output before upgrading.

Smart Proxy TLS cipher restrictions

Custom Smart Proxy cipher restrictions might not apply to every enabled TLS version. On Ruby/OpenSSL builds without SSLContext#ciphersuites=, tls_ciphers does not restrict TLS 1.3 ciphers. A cipher string valid for only one TLS version can also leave another enabled version unrestricted by that string. Test the effective cipher configuration for each enabled TLS version.

2. Katello 5.1 release notes

2.1. Headline features

Container image push from Smart Proxies

Smart Proxies can now pull container images from and push them to the container registry on Foreman server by using their SSL client certificate. Enable this per Smart Proxy with the Container Registry Authentication checkbox or the container_registry_auth_enabled API parameter. A Smart Proxy can only access container repositories of the organizations it is assigned to. New repositories created by pushing container images are now stored as regular container repositories in Pulp.

Debug certificate algorithm selection

The download_debug_certificate API endpoint now accepts the optional key_algorithms and signature_algorithms parameters, which take algorithm OIDs and are passed to Candlepin. The Edit Organization page has a new drop-down list for the debug certificate algorithm, which offers the key algorithm of the Candlepin CA certificate. On most deployments, this is RSA only. This prepares Katello for deployments that use post-quantum cryptography algorithms such as ML-DSA. If you omit these parameters, the debug certificate is generated as before.

Download policy for Python repositories

You can now set the download policy of Python repositories to On Demand or Immediate, as for other repository types. New Python repositories use the Default Custom Repository download policy setting, which defaults to Immediate.

Files pages migrated to PatternFly 5

The Files list and file details pages have been moved to the generic content pages, which use the PatternFly 5 design standard. The file details page shows the Library repositories and content views that contain the file.

New Hammer subscription manifest and repository information

The new hammer subscription manifest-info command shows the subscription manifest details of an organization. The hammer repository info command now shows whether a repository is orphaned.

Pulp 3.118 required

Katello now requires Pulp 3.118. If you interact directly with Pulp APIs, consult the Pulp changelog for changes since Pulp 3.105.

2.2. Upgrade warnings

Allow multiple content views setting removed

The allow_multiple_content_views setting has been removed. Hosts and activation keys can always have multiple content view environments, which was already the default behavior. Before the upgrade, if allow_multiple_content_views was false, registration with multiple activation keys assigned only the content view environment from the last key that had an environment. After the upgrade, registration assigns the content view environments from all the keys. Remove the setting from any scripts or automation.

Content view and lifecycle environment host columns removed

The separate Content view and Lifecycle environment columns have been removed from the All Hosts page, the legacy Hosts page, and the host CSV export. Use the Content view environments column instead. Update any scripts that parse the Content View or Lifecycle Environment columns of the host CSV export.

Subscription allocation permission scoped to organizations

The manage_subscription_allocations permission is now enforced per organization. During the upgrade, the resource type of this permission changes from Subscription to Organization. Users can manage subscription allocations only in organizations that their role covers. Review custom roles that grant manage_subscription_allocations.

Download policy of Python repositories

Before Katello 5.1, Python repositories always used the On Demand download policy. During the upgrade, existing Python repositories are set to On Demand, so their behavior does not change. Python repositories that you create after the upgrade use the Default Custom Repository download policy setting, which defaults to Immediate. To download Python content only when it is requested, set the download policy of new Python repositories to On Demand.

2.3. Deprecations

There are no deprecations with Katello 5.1.
